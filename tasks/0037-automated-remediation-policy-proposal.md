# Task 0037 — Automated remediation policy proposal

**Status:** Proposed (not assigned)
**Milestone:** Future
**Roadmap item:** Evaluate automated remediation as a separate proposal.

## Scope

Decide whether any remediation capability belongs in this project and, if so, identify strict user-consent, privilege, reversibility, and audit boundaries before proposing a narrowly bounded action.

## Acceptance criteria for a future planning task

- Compare the proposal against the current non-goal of automatic network changes and the project’s read-only, unprivileged default.
- Document failure modes, false-positive consequences, required user confirmation, privilege needs, rollback limits, and audit/privacy implications.
- Recommend reject or propose one specific action with a separate threat and safety review.
- Require explicit approval to change project policy before any remediation implementation task is created.

## Boundary

This proposal authorizes no automatic or manual remediation command, network-setting change, elevated permission, or service restart. The current non-goal remains in force unless the project owner explicitly revises it.
